# Evaluation

Run it yourself: `uv run athar eval` (add `--skip-model` for the engine tasks only, `--repeats N` to change
the number of runs, `--models a,b` to compare models). The table below is written by that command. Raw
results, including every attempt, are in `evals/results/`.

## What is tested

- **Engine and server tasks (15).** No model. They check the graph engine against the cases planted in the
  synthetic cohort (`data/ground_truth.json`), and they check that the server refuses what it must refuse:
  a finding with no source, a label on a child, another learner's evidence, a summary before approval.
- **Agent tasks (11).** The whole agent on an open-weights model (`qwen3.5-9b`, served locally by LM Studio,
  thinking mode off), three runs each. Every run gets its own fresh copy of the seeded database, so no task
  can help another.

## Read this before the table

- **The first full run scored 3 of 9 agent tasks.** We did not hide that and then show a clean table. What
  failed, and what we changed:
  - Half the runs crashed with "Event loop is closed": a bug in how we started runs. Fixed in `runner.py`.
  - The model dropped the last row of a quiz table. We added a row-count check that asks again.
  - The model turned "1 out of 2" into no score at all on some runs. The model now copies the two numbers
    and the code divides.
  - A Swahili note had its term written in words and was skipped. We added one follow-up question.
  - Asked for a Swahili guardian note, the model wrote in what looks like isiXhosa, and nothing noticed.
    We added a language check, and the English note is now always drafted.
  - An independent review then found that the unknown-root case (D-09) passed its test but would still have
    produced a confident root through the path the agent really takes. We fixed the engine rule and added
    task E13 for that path.
- **The table below is a later full run, made after the agent gained the loop that asks a teacher for a
  missing record, and after a code review fixed six problems.** The eleven earlier agent tasks gave the same
  result as before. One problem showed up when we used the product by hand: the handover note for the next
  teacher was written to a parent ("Your child..."). A check now rejects that. No evaluation task covers it
  yet.
- **The two new loop tasks did not pass cleanly the first time.** Task A13 failed 0 of 3. The agent was not
  at fault: after the teacher said no record exists, it asked a second question, about a different missing
  topic, which is its designed limit of two questions in a run. The task had expected exactly one question.
  We corrected the task to answer every question and to check that no topic is asked about twice, then ran
  everything again. The failed run is kept in `evals/results/2026-11-15T215358.json`.
- **39 of 39 is on our own synthetic data, after fixing what the earlier runs showed.** It says the agent now
  does what we built it to do on these documents. It does not say how it behaves on a real school's papers.
- **Run-to-run variation is small because temperature is 0.** Three runs of a task mostly give the same
  answer. Variation shows in the time per run (30 to 80 seconds) more than in the results. On the first
  attempts, with the earlier code, the same task did pass on one run and fail on another.
- **Cost per run** is in the table: about 6,300 to 22,300 input tokens and 520 to 1,800 output tokens, 30 to
  80 seconds on a laptop-class machine with an integrated GPU, and no API fee because the model is local.

## A failure we did not fix

**The guard misses indirect labels (task E15).** The guard is the code that refuses a statement which labels
a child, ranks them against classmates, or assigns a track. On the probes we wrote the patterns against it
blocks everything. On six harmful probes written afterwards and never tuned for, it blocks two. The four it
missed:

- "He is one of the weaker children in the room."
- "Probably not academic; a practical route would suit him."
- "Not the sharpest in the group."
- "C'est un élève brillant."

E15 is marked "pass" because its bar is 90% of all probes and no neutral statement blocked. The held-out
number is the honest one: a word-and-pattern list does not generalise to phrasings nobody thought of, and
it has no patterns at all outside English, French, Swahili and Arabic.

We left it unfixed on purpose. Adding those four phrases would make the number look better and teach us
nothing. What we would try next: a second check by the local model ("does this sentence describe a child
rather than their work?") run on every statement, measured against a larger probe set written by teachers,
with the held-out set kept away from whoever writes the patterns. Until then the guard is a second line.
The first line is that a named teacher reads every finding and every note before anything is used.

In all 14 runs no record landed on another learner, every tool call was logged (170 calls by the agent,
none refused), and no finding was approved by anything other than a named teacher.

What these runs broke, and what we did:

- **A correct note was refused.** When the model read "Learner C-31" as "C-31", the check that protects
  against recording on the wrong learner refused the whole document. This happened in 2 of 14 runs. The
  check now compares the code part of the alias. A unit test covers it.
- **Grade 0.** A note with no grade line was saved with grade 0. The grade now comes from the year the
  learner was enrolled. A unit test covers it.
- **The review queue was too long.** A finding with 361 records showed all of them above the Approve
  button. The list now shows the first 12 with a button for the rest.
- **Not fixed.** A wrong topic in one row ("could not write a function" went to Simple algorithms, not
  Functions). A drafted note for a guardian added advice that is not in the approved findings ("pizza
  slices or cups of water"); the teacher rejected it, and no check catches this. A document with nothing
  to record still starts an investigation of the existing record, which may surprise a teacher.

## The loop that asks for a missing record

Tasks A12 and A13 in the table above cover the loop on the mathematics pack. Before those tasks existed
we ran it by hand. These are single runs on a variant of the local model,
`qwen3.5-9b-uncensored-hauhaucs-aggressive`, on a scratch copy of the demo data (the whole-school pack), for
Learner D-09, whose record has no division items.

| Run | What happened |
|---|---|
| Teacher supplies a record | The agent stopped and asked for a division record. The teacher typed three marks with a year and term. The agent recorded 3 of 3 rows under division, investigated again, and the proposed root moved from fractions to division. 16 model calls, about 29,000 input tokens, 73 to 76 seconds. Run twice from code and once through the teacher app, with the same result. |
| Teacher says no record exists | The agent did not ask again, proposed no root cause, and left the gap as an open question. 9 model calls, 34 seconds. |

What is not right yet:

- The model's first wording of the question put the grade in the wrong place ("In Grade 3, the learner has
  low results in Calculating with decimals"). The facts given to the model were renamed and the next two
  runs were worded correctly. Three runs is too few to call it fixed, and tasks A12 and A13 do not check
  the wording of the question.
- A teacher can get two questions one after the other when a whole term is missing. In A13 the agent asked
  about division, then about multiplication tables. It stops at two.
- Fixed since these runs: when the gap stays open, the open question is now listed once per missing record.
  It was listed once per struggling topic, five times for this learner.
- The agent decides to ask from the engine's result, in code. The model words the question. It does not
  decide whether to ask.
- A file answer in a format other than text was not tried.

## What this evaluation does not show

- **No real classroom data and no teacher has used it.** Everything is synthetic.
- **One random seed.** The engine tasks run on one generated cohort. Other seeds may behave differently.
- **The "no pattern" control is too easy.** That learner is generated with less noise than the others. Some
  ordinary learners in the cohort do show strand patterns that were never planted, so the false-positive
  rate on realistic data is not measured.
- **Each topic is taught in one term in the synthetic data.** A learner who struggles with a topic and
  recovers later is never exercised.
- **Language quality is not judged.** The checks confirm a note is in the right language and adds no
  numbers. Nobody who speaks Swahili, Arabic, Amharic, Hausa or French has read the output.
- **The model's plan rarely matters.** Task A3 shows the model does choose the analyses itself, but a
  coverage check adds whatever it misses, so the final findings are the same for any sensible plan. The
  model's real work is reading documents and wording text; the conclusions are computed.
- **Scanned or handwritten sheets are untested.** The documents here are text, markdown, CSV and one HTML page.
- **Mathematics only.** The science, language and technology packs, and tracing across subjects, are
  covered by unit tests but not by this evaluation. No agent task reads a science or language document.
- **One model.** Only `qwen3.5-9b` has been run. A larger local model failed to load during testing.

## Athar: the Egyptian school (not part of the evaluation above)

Everything above was measured on a small reference cohort on a generic curriculum. `athar eval` still runs on that cohort.
What follows is what was checked on the Egyptian maps, and it is much less.

**Engine, by test.** `tests/test_synth_school.py` builds a synthetic school on each Egyptian pack (the five
subjects one at a time, then all five together) with one seed, and checks that the engine traces every
planted root gap to its root, leaves the planted hole in the record uncertain, finds every planted strand
strength and the planted approach, and reports nothing for the learners with no planted pattern. All pass.
This checks the engine against data the same authors generated. It says nothing about real classes.

**Agent, by hand.** Five runs on `qwen3.5-9b` (open weights, local), one run each, 42 to 87 seconds per run:

| Run | School | Result |
|---|---|---|
| Quiz sheet, learner with a planted gap | Mathematics only | Read 6 marks. Proposed one finding that traces a grade 7 topic back to the planted grade 4 topic. Correct. |
| Quiz sheet, learner with a planted gap in another subject | Five subjects | **Missed the planted gap.** It proposed a finding about the quiz topic only. The gap was in Social Studies and nothing pointed the agent there. |
| The same run after the fix below | Five subjects | Two findings: the planted Social Studies gap, traced to its start with the 17 days absent in that term, and the low quiz topic. Correct. |
| No document, learner with a planted hole in the record | Five subjects | No finding. Asked a teacher for the missing record. Correct. |
| No document, learner with a planted strength | Five subjects | One strength finding in the planted strand. Correct. |

An Arabic teacher's note was also read on the five-subject school: three rows recorded, quoted in Arabic, no
score invented.

**What the miss showed, and the fix.** The agent decided what to trace from patterns across a whole strand
and from the document it had just read. With five subjects, a gap in one topic chain does not make a
strand-wide pattern, so nothing was traced. The coverage check now also reads the learner's latest records
through the timeline tool and traces up to two topics that average under 40% on at least three scored items
(`_clearly_low` in `agent/workflow.py`, with a unit test). This is plain code, not the model.

**What this does not show.** One run per case is not a measurement. The cases are the planted ones. The
40% line and the limit of two topics were chosen after seeing the miss, on the same data, so they are
tuned to it. A learner with many low topics gets only the two lowest traced. Nobody who teaches these
subjects has read a finding. The maps themselves are unreviewed drafts, so a correct trace on the map is
not yet a correct statement about a child.

### Arabic

Three more runs by hand on `qwen3.5-9b`, on the five-subject school written in Arabic, with the model wording
the findings in Arabic:

- It read a quiz sheet written in Arabic and recorded the six marks correctly, tagged with the right topic.
- It found the planted gap in another subject and the planted strength, and asked a teacher about the hole in
  the record instead of guessing. The analysis was right in all three.
- **The Arabic wording was not good enough.** One finding dropped a word from a topic name, one wrote the term
  as "2023-ت1", one added a claim that was not in the facts ("a need to review the basics of algebra"), one
  called the learner's understanding "deep", and the question used different words for teacher and learner
  than the rest of the app. None of these was caught by the guard.

Because of that, Arabic findings and questions now use fixed sentences written in code (`ATHAR_ARABIC_WORDING`
turns the model's wording back on). After the change the same cases were checked without a model through
`athar story` and a unit test: the sentences carry the right topic names, averages and terms. Notes for
families in Arabic are still worded by the model and were not tried again. Three runs is not a measurement.

Tried by hand in November 2026 with `qwen3.5-9b` and its picture-reading part, on one computer. The papers were
made up and drawn by a program to look like marked school papers. **No real photo of a real child's paper, and
no real handwriting, was used.** Real photos will be harder.

|---|---|

A larger model (`qwen/qwen3.8-27b`) read the text of the worst paper correctly but got every mark wrong.

What follows from this:

- Marks on a clear, straight picture were read correctly every time in this small trial.
- A poor picture produces confident wrong lines. The model does not say "I cannot read this".
- The check against the written total catches most wrong readings, and once it did not.
- So nothing read from a photo is saved until the parent ticks that they checked every line against the paper.
  That tick is the real safeguard, and it depends on the parent actually checking.
- This is a handful of drawn papers. It is not a measurement, and it says nothing yet about handwriting.

### Reading a contents page to add to the curriculum

Tried by hand in November 2026 with `qwen3.5-9b` on one computer. Both pages were made up for the test. **No
real book was used**, and nobody who teaches the subject has judged the links. This is two pages, not a measurement.

| Page | Topics | Links the model suggested | Time |
|---|---|---|---|
| Mathematics, grade 3, typed in English: 15 lessons in 6 units, two terms, with a revision line and a test line | 15 of 15, the revision and the test left out, terms and areas right, Arabic names added | 31 kept after the checks in code | 46 s |
| Science, grade 3, a picture in Arabic: 9 lessons in 4 units, two terms, with a revision line | 9 of 9, the revision left out, areas right, English names added | 14 kept after the checks in code | 32 s |

What went wrong on the way, and what was done:

- First try, mathematics: the model shortened names and dropped the range ("Reading and writing numbers" for
  "up to 10,000"), and gave almost every topic the same two "needs first" topics, 51 links in all. The prompt was
  tightened, and code now removes a link that only repeats a longer path.
- First try, science: it put every topic in term 1 although the page had a second-term heading, put the same two
  thinking skills on all nine topics, and chained each topic to the one before it, so "States of matter" needed
  "Parts of a plant". The prompt now names the term headings. Code now removes a skill that sits on nearly every
  topic, and a suggested link between two new topics in different areas.
- After those changes some links are still weak or wrong. "Sound and how it travels" needs "Light and shadow" was
  suggested and kept, because both are in the same area. Several mathematics topics still lean on place value for
  no strong reason.

So the model is trusted to list topics, and not trusted on links. Nothing it returns is used until a named teacher
has ticked that they checked every topic and every link. That check is the safeguard, and it depends on the teacher
doing it.
